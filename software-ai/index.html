Details

Fills walk the real order book: a paper market order is filled level by level against a live Binance depth snapshot, at the volume-weighted price, plus a taker fee; if the book is too thin the order is rejected. paper_execution.py · walk_book

Stocks only trade in market hours: stock orders fill only inside the NYSE regular session, at the quoted bid or ask; a missing quote makes the slippage an explicit estimate.

Drawdown kill switch: each account tracks its peak equity; a drawdown past the limit (10% by default) pauses that account's autopilot — no forced selling — records why it fired, and only an explicit user command resumes it. live_bot_engine.py

No made-up prices: when market data is missing the order is rejected; a static test fails the suite if fabricated data finds its way back into the runtime. No order ever leaves the machine: the code has no exchange order endpoint to call.

Details

Turns PDF books into narrated Turkish audio — OCR fallback, LLM cleanup, text-to-speech with sentence highlight, quizzes and a voice discussion mode. The screenshots were captured by CI from the demo build (mock AI answers, silent audio); the UI is English, the sample book is a public-domain Turkish story.

Private lesson: pick a chapter and the app splits it into parts, explains each in plain Turkish — even when the book is in English — asks one or two questions only that part can answer, grades each answer as correct, half or wrong, and saves progress on the phone.

Each text-to-speech service implements one method; settings pick which one runs, so swapping a provider does not touch the reader. The gate runs analysis with warnings as errors, a scenario probe for what unit tests do not pin down, and a coverage script that reads the report itself.

Orphan files count as red: coverage tools skip files no test imports, so the gate lists every logic file and fails if one is missing. The UI is out of scope — and says so: the 100% floor covers business logic only. No mutation leg: no mutation tool for Dart could be proven here, so that step reports red on purpose.

Details

The gate is a set of scripts, git hooks and CI jobs copied into every repository from one template. The planner agent must prove “red first” with a fresh failing-test log; a role guard diffs the implementer's work against a snapshot so it cannot touch tests; editor hooks block out-of-role edits. The gate runs on GitHub Actions and locally as a twin of CI tied to the exact commit — it grades only by exit codes. One command, one verdict: each step must exit 0, and pytest carries --cov-branch --cov-fail-under=100, so a single untested branch turns the run red.

The gate is tested too. Self-tests feed it broken code on purpose and expect red; attack self-tests try known bypasses — editing a test, staging a file outside scope, hiding a “no cover” pragma, rewriting the plan — and each must be blocked; a run that skipped its steps or found zero tests is reported as a failure.

Four ways a test can't fail

How it spots a weak assert

diagram · from scripts/dissiz_check.py
Details

AI agents are very good at producing tests that pass. Some pass because they cannot fail: they check nothing, or they swallow the error that should have failed them. The detector — “dissiz” is Turkish for toothless — reads every test's syntax tree with Python's ast module (no test is run) and flags four patterns: returns a value instead of asserting, has no assert, uses only weak asserts, or has an except handler that swallows the error. In one repository its count went from 45 to 14; what remains sits in a baseline file, and any new toothless test turns the gate red. The detector has its own test suite.

How I work with AI agents

Three rules, every repository
  1. 01 · RED

    Spec and failing tests first

    I write what "done" means as tests that fail before any code exists.

  2. 02 · AGENTS

    Role-separated agents

    One agent plans, another implements; the author never grades its own work.

  3. 03 · GREEN

    The automated gate decides

    Lint, types, tests and coverage run in CI, plus mutation testing where a tool exists. Merge happens only on green.

Story

Why I shut down my 2,900-file guardrail system

Every agent mistake got a new watcher, until there were many rules and very little product. I learned that the goal is finished work, so I kept only the checks for problems I had measured again and again — and packed them so other people can start there.

Before: 7 hooks · 6 git hooks · 4 workflows · 26 self-tests · about 2,900 tracked evidence files
Distilled from about 3,300 of my messages to agents (raw transcript entries) · 168 requests
Now: 301 tests · 98.6% coverage · CI in 24 s · MIT licence

A guardrail, not a sandbox: it catches common mistakes, not a determined attacker. The night-watchman hook is opt-in and not installed by default.
